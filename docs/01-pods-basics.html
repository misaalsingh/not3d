Deep Dive

📦 What is a Pod?

A Pod is the atomic unit of scheduling in Kubernetes — you don't deploy containers directly, you deploy pods. Containers in the same pod share:

  • ● The same network namespace (same IP, can talk via localhost)
  • ● The same IPC namespace (can share memory)
  • ● Volumes mounted into the pod
💡

Why does Kubernetes use Pods instead of raw containers?

Pods allow tightly-coupled processes (like a web server + log shipper) to be co-located and share resources, while still being independently versioned containers. This keeps containers focused on a single responsibility.

🔄 Pod Lifecycle Phases

PENDING

Pod accepted by the cluster, but containers not yet running. May be waiting for image pull or node scheduling.

RUNNING

Pod bound to a node. At least one container is running, starting, or restarting.

SUCCEEDED

All containers terminated with exit code 0 and will not be restarted. Common for batch Jobs.

FAILED

At least one container terminated with a non-zero exit code, or the system terminated the container.

UNKNOWN

Cannot determine pod state — typically because the node has lost communication with the control plane.

🛠️ Creating Pods

bash 
kubectl run nginx --image=nginx --port=80

🎯 CKA Tip: The imperative command is fastest during exams. Add --dry-run=client -o yaml to generate YAML you can then edit!

kubectl run nginx --image=nginx --dry-run=client -o yaml > pod.yaml
pod.yaml 
apiVersion: v1
kind: Pod
metadata:
  name: nginx-pod
  labels:
    app: nginx
spec:
  containers:
  - name: nginx
    image: nginx:1.25
    ports:
    - containerPort: 80
bash — apply the YAML 
kubectl apply -f pod.yaml

📌 Note: The 4 required YAML fields are apiVersion, kind, metadata, and spec. Forgetting any of these will cause a validation error.

🔍 Troubleshooting Pods

Follow this mental model when a pod isn't behaving correctly:

1
kubectl get pods

Check STATUS and RESTARTS columns. High restarts = crash loop.

2
kubectl describe pod <name>

Look at the Events section at the bottom for scheduling and image pull errors.

3
kubectl logs <pod-name>

Application-level errors. Add --previous to see logs from a crashed container.

4
kubectl exec -it <pod-name> -- /bin/bash

Get a shell inside to inspect environment, network connectivity, file contents.

Short Answer — Reveal

❓ Why are pods considered "ephemeral" and what does that mean for data storage?

Ephemeral means pods can be killed, rescheduled, or replaced at any time. Any data written inside a container's filesystem is lost when the pod dies. For persistent data, you must use PersistentVolumes (PV) and PersistentVolumeClaims (PVC) which exist independently of the pod lifecycle.

❓ What is the difference between the Ambassador and Adapter multi-container patterns?

Ambassador focuses on outbound communication — it proxies requests from the main container to external services, abstracting away discovery/routing.

Adapter focuses on output transformation — it takes the main container's output and converts it to a standard format for external consumers (e.g., Prometheus metrics).

❓ A pod is in "Unknown" state. What is the most likely cause?

The node where the pod is running has lost communication with the Kubernetes control plane (API server cannot reach the kubelet on that node). Check node health with kubectl get nodes and look for NotReady status.

Command Reference

Command Description Copy
kubectl get pods List all pods in current namespace
kubectl get pods -o wide List pods with IP address and node info
kubectl describe pod <name> Show detailed info + events for a pod
kubectl logs <pod-name> View stdout logs from the pod
kubectl logs <pod> -c <container> Logs for a specific container in multi-container pod
kubectl logs <pod> --previous Logs from the previously terminated container
kubectl exec -it <pod> -- /bin/bash Open an interactive shell in a pod
kubectl delete pod <name> Delete a pod
kubectl run nginx --image=nginx --dry-run=client -o yaml Generate pod YAML without creating it (CKA trick)
kubectl apply -f pod.yaml Create or update resources from a YAML file
